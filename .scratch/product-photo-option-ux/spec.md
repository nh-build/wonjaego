# 상품 사진 등록 + 옵션 입력 UX 개선

## Problem Statement

셀러는 상품 목록/상세를 텍스트(상품명·SKU)만으로 구분해야 해서, 상품이 많아질수록 사진 없이는 한눈에 알아보기 어렵다. 특히 모바일에서 재고를 기록하는 도중 바로 사진을 찍어 붙일 방법이 없다.

또한 상품 등록 화면의 옵션 입력란이 옵션을 안 쓰는 상품(대부분)에게도 항상 5줄을 그대로 보여줘서, 화면이 불필요하게 길고 산만하다.

## Solution

상품 등록/수정 화면에서 사진을 한 장(선택) 업로드할 수 있게 하고, 모바일에서는 파일 선택 대신 바로 카메라로 촬영할 수 있게 한다. 업로드한 사진은 상품 목록에 작은 썸네일로, 상품 상세에 큰 사진으로 표시된다. 사진은 로그인한 소유자만 볼 수 있다. 저장은 서버 로컬 폴더를 쓰되, 나중에 클라우드 스토리지로 바꿔도 Product/서비스 코드를 건드리지 않도록 저장소 접근을 인터페이스 뒤로 감춘다.

옵션 입력란은 처음엔 한 줄만 보여주고, "+" 버튼을 누를 때마다(최대 5줄까지) 한 줄씩 더 보여준다. 각 줄에는 "×" 버튼으로 그 줄만 비울 수 있다. 백엔드가 이미 5칸을 받도록 돼 있으므로, 이 변경은 화면(자바스크립트)만으로 이뤄진다.

## User Stories

1. As a 셀러, I want 상품 등록 화면에서 사진을 한 장 선택해 올릴 수 있길, so that 등록과 동시에 상품을 시각적으로 구분할 수 있다.
2. As a 셀러, I want 상품 수정 화면에서도 사진을 새로 올려 기존 사진을 바꿀 수 있길, so that 나중에 더 나은 사진으로 교체할 수 있다.
3. As a 셀러, I want 사진을 올리지 않고도 상품을 등록·수정할 수 있길, so that 사진이 필수 항목이 되어 등록을 막지 않는다.
4. As a 모바일 셀러, I want 사진 입력란을 누르면 바로 카메라가 열리길, so that 사진을 미리 찍어둘 필요 없이 그 자리에서 촬영해 올릴 수 있다.
5. As a 셀러, I want 지원하지 않는 형식(JPEG/PNG/WebP 외)이나 너무 큰 파일(5MB 초과)을 올리면 에러 메시지와 함께 거부되길, so that 알 수 없는 이유로 등록이 실패하지 않는다.
6. As a 셀러, I want 상품 목록에서 각 상품의 작은 썸네일을 볼 수 있길, so that 상품명을 읽지 않고도 빠르게 상품을 알아볼 수 있다.
7. As a 셀러, I want 상품 상세 화면 상단에서 큰 사진을 볼 수 있길, so that 상품을 자세히 확인할 수 있다.
8. As a 셀러, I want 사진이 없는 상품은 목록·상세에서 플레이스홀더로 표시되길, so that 빈 자리가 깨져 보이지 않는다.
9. As a 셀러, I want 다른 회원의 상품 사진 URL을 직접 열어도 볼 수 없길(404), so that 내 상품 사진이 다른 사람에게 노출되지 않는다.
10. As a 셀러, I want 로그인하지 않은 상태로 상품 사진 URL에 접근하면 로그인 화면으로 리다이렉트되길, so that 비로그인 사용자에게 노출되지 않는다.
11. As a 셀러, I want 사진이 있던 상품을 삭제하면 그 사진 파일도 함께 정리되길, so that 서버에 안 쓰는 파일이 계속 쌓이지 않는다.
12. As a 셀러, I want 사진을 다시 올려 교체하면 이전 사진 파일이 자동으로 지워지길, so that 안 쓰는 이전 파일이 서버에 남지 않는다.
13. As a 셀러, I want 상품 등록 화면의 옵션 입력란이 처음엔 한 줄만 보이길, so that 옵션을 안 쓰는 대부분의 상품 등록 화면이 간결하다.
14. As a 셀러, I want "+" 버튼을 눌러 옵션 입력 줄을 하나씩 늘릴 수 있길, so that 필요한 만큼만 옵션 그룹을 입력할 수 있다.
15. As a 셀러, I want 옵션 입력 줄이 최대 5개까지 늘어나고 그 이상은 "+" 버튼이 비활성화되길, so that 실수로 너무 많은 옵션 그룹을 만들지 않는다.
16. As a 셀러, I want 각 옵션 입력 줄의 "×" 버튼으로 그 줄의 입력값만 비울 수 있길, so that 잘못 입력한 옵션 그룹을 쉽게 정리할 수 있다.
17. As a 셀러, I want 옵션 입력 줄을 늘리거나 지워도 페이지가 새로고침되지 않길, so that 입력하던 다른 값(상품명·가격 등)이 유지된다.

## Implementation Decisions

- **`Product.photoKey`**: nullable String 필드 추가. 파일 경로가 아니라 저장소가 발급한 불투명한 키를 저장한다(구현 세부사항이 DB 스키마에 새지 않도록).
- **`FileStorage` 인터페이스** (`com.wonjaego.storage` 패키지): `store`/`load`/`delete`를 키 기반으로 제공하는 추상화. MVP 구현체는 `LocalFileStorage` 하나뿐이며, 서버 로컬 폴더(설정 가능한 base 디렉터리)에 저장한다. `docs/adr/0003-product-photo-storage-abstraction.md` 참고.
- **상품 등록/수정 폼**: `enctype="multipart/form-data"`로 전환하고, 선택적 파일 필드를 추가한다. 파일 input은 `accept="image/*" capture="environment"`로, 모바일에서 후면 카메라를 바로 열도록 한다.
- **파일 검증**: 허용 형식은 JPEG/PNG/WebP, 최대 크기는 5MB. 형식·크기를 벗어나면 폼 에러로 처리해 등록/수정 화면에 에러 메시지를 보여준다(등록/수정의 다른 입력값은 유지).
- **업로드 흐름**: 상품 생성 시 사진이 함께 제출되면 저장 후 키를 기록한다. 수정 시 새 사진이 제출되면 기존 파일을 삭제하고 새로 저장한다. 사진 없이 수정을 제출하면 기존 사진은 그대로 유지된다(이번 범위에서는 "사진만 삭제"하는 별도 기능은 만들지 않는다).
- **사진 서빙**: `GET /products/{id}/photo` — 로그인 + 해당 Product 소유자만 접근 가능(기존 `getOwned` 소유권 검사 패턴 재사용). 사진이 없거나 소유자가 아니면 404. 비로그인 접근은 기존 인증 흐름대로 로그인 화면으로 리다이렉트된다.
- **상품 삭제 시 정리**: Product 삭제가 허용되는 경우(참조하는 Movement가 없을 때), 연결된 사진 파일도 `FileStorage.delete`로 함께 정리한다.
- **표시**: 상품 목록 테이블에 작은 썸네일 컬럼, 상품 상세 화면에 큰 사진을 추가한다. 사진이 없는 상품은 플레이스홀더(아이콘/이니셜 등)로 표시한다.
- **옵션 입력 UX**: `ProductCreateForm.optionGroups`(5칸 고정)는 변경하지 않는다. 화면(Thymeleaf + 바닐라 자바스크립트)만 바꿔서, 5개 입력 줄 모두 DOM에는 존재하되 2~5번째 줄은 초기에 숨겨 놓는다. "+" 버튼은 숨겨진 줄 중 가장 앞의 것을 보여주고, 5줄이 모두 보이면 비활성화된다. 각 줄의 "×" 버튼은 그 줄의 두 입력값을 비우며, 2~5번째 줄이면 다시 숨긴다(1번째 줄은 항상 보임). 백엔드로 제출되는 필드 이름·구조는 기존과 동일하다.

## Testing Decisions

- 기존과 동일하게 **단일 컨트롤러 seam**(MockMvc 풀스택 + 실제 test H2)으로 검증한다. 사진 업로드는 MockMvc의 `multipart()` 요청 빌더로 실제 멀티파트 요청을 보내고, `LocalFileStorage`는 test 프로필 전용 임시 디렉터리에 실제로 파일을 쓰고 읽는다 — 별도 유닛 테스트 seam은 추가하지 않는다. 업로드→저장→서빙(`GET /products/{id}/photo`) 전체 흐름이 이 하나의 통합 테스트로 커버된다.
- 테스트 대상: 사진 있는/없는 상품 등록, 사진 교체(이전 파일 정리 확인), 지원하지 않는 형식/크기 초과 거부, 사진 서빙의 소유권 404 및 비로그인 리다이렉트, 상품 삭제 시 사진 파일 정리, 상품 목록/상세에서 썸네일·사진 노출 확인.
- 옵션 입력 줄 추가/삭제(자바스크립트 동작)는 서버 사이드 테스트 대상이 아니다 — 백엔드 폼 구조(`optionGroups` 5칸, 트림/중복 제거, 빈 슬롯 무시)는 이미 검증되어 있고 이번 변경으로 바뀌지 않는다.
- Prior art: 기존 `ProductCrudTest`(등록/수정 흐름, ownership 404 패턴)와 동일한 구조를 따른다.

## Out of Scope

- 사진 여러 장 등록 (Product당 정확히 1장만).
- 사진만 삭제(재업로드 없이)하는 기능.
- ProductVariant 단위 사진(사진은 Product 레벨에만 붙는다).
- 실제 클라우드 스토리지 구현체 (인터페이스만 두고, 로컬 구현체만 만든다).
- 옵션 입력 줄 최대 개수를 5개 이상으로 늘리는 것(백엔드 폼 구조 변경 없음).
- 이미지 리사이즈/압축, EXIF 처리 등 이미지 가공.

## Further Notes

두 기능(사진, 옵션 UX)은 같은 상품 등록 화면(`products/list.html`)과 상품 수정 화면(`products/edit.html`)에 함께 반영되므로 한 스펙으로 묶었다. 티켓 분해 시에는 서로 독립적으로 나눌 수 있다 — 사진 기능은 스키마·저장소·컨트롤러·테스트가 필요한 반면, 옵션 UX는 순수 프론트엔드(템플릿 + 자바스크립트) 변경이라 별도 티켓으로 분리하는 것을 권장한다.
