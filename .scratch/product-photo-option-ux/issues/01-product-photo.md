# 01 — 상품 사진 등록·표시·서빙

**What to build:** 셀러가 상품 등록/수정 화면에서 사진 한 장을 선택적으로 올릴 수 있다(모바일에서는 바로 카메라 촬영). 올린 사진은 상품 목록에 썸네일로, 상세 화면에 큰 사진으로 보이며, 로그인한 소유자만 볼 수 있다. 저장소는 인터페이스 뒤에 감춰져 있어 나중에 클라우드로 바꿔도 Product/서비스 코드를 건드릴 필요가 없다.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [x] `com.wonjaego.storage` 패키지에 `FileStorage` 인터페이스(`store`/`load`/`delete`, 키 기반)와 그 유일한 구현체 `LocalFileStorage`(설정 가능한 로컬 base 디렉터리에 저장)가 있다.
- [x] `Product`에 nullable `photoKey`(String) 필드가 있다 — 파일 경로가 아니라 저장소가 발급한 키를 저장한다.
- [x] `/products` 등록 화면에서 사진 파일을 선택해(선택 사항, 필수 아님) 상품과 함께 등록할 수 있다. 파일 input은 `accept="image/*" capture="environment"`로, 모바일에서 후면 카메라가 바로 열린다.
- [x] JPEG/PNG/WebP 외 형식이나 5MB를 초과하는 파일을 올리면 등록/수정이 거부되고 에러가 화면에 표시된다(다른 입력값은 유지).
- [x] `/products/{id}/edit` 수정 화면에서 새 사진을 올리면 기존 사진 파일이 삭제되고 새 사진으로 교체된다. 사진 없이 수정을 제출하면 기존 사진은 그대로 유지된다.
- [x] `GET /products/{id}/photo`는 로그인 + 해당 Product 소유자만 접근 가능하다 — 다른 회원 소유 상품이거나 사진이 없으면 404, 비로그인 상태면 로그인 화면으로 리다이렉트된다.
- [x] 상품 목록 테이블에 각 상품의 작은 썸네일이, 상품 상세 화면 상단에 큰 사진이 표시된다. 사진이 없는 상품은 플레이스홀더로 표시된다.
- [x] Product 삭제가 허용되는 경우(참조하는 Movement가 없을 때), 연결된 사진 파일도 함께 삭제된다.
- [x] MockMvc의 `multipart()` 요청으로 실제 파일 업로드를 보내고, test 프로필 전용 임시 디렉터리에 실제로 저장/조회/삭제되는 것을 검증하는 테스트가 있다 — 사진 있는/없는 등록, 사진 교체(이전 파일 정리 확인), 형식/크기 초과 거부, 서빙의 소유권 404·비로그인 리다이렉트, 삭제 시 파일 정리, 목록/상세 표시를 포함한다.
