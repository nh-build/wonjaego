# 대시보드 상품 카드의 채널 칩은 상품별 실제 연결이 아니라 셀러의 전체 등록 채널을 보여준다

메인 화면(대시보드) 재설계에서 각 상품 카드에 판매채널 칩(스마트스토어/에이블리/지그재그 등)을 붙이기로 했다. 그런데 이 프로젝트의 도메인 모델에는 "이 Product가 이 SalesChannel에서 팔린다"는 직접적인 연결이 없다 — `SalesChannel`은 셀러가 등록/관리하는 독립 엔티티이고, `Movement`가 어느 채널에서 발생했는지 태그로만 기록한다([CONTEXT.md](../../CONTEXT.md) 참고).

## Considered Options

- **Movement 이력에서 실제 거래된 채널만 표시**: 가장 정확하지만, 아직 입출고 기록이 없는 신규 상품은 칩이 하나도 안 뜬다. 상품마다 다른 조회 쿼리(변형별 Movement distinct channel)가 필요해 구현 비용도 크다.
- **셀러의 전체 등록 채널을 모든 상품 카드에 동일하게 표시 (채택)**: `SalesChannelService.listOwned(memberId)` 결과를 모든 상품 카드에 그대로 붙인다. 항상 데이터가 있고 구현이 간단하지만, "이 상품이 실제로 이 채널에 올라가 있다"는 의미는 아니다 — 셀러가 등록한 채널 목록을 보여줄 뿐이다.

## Consequences

- `HomeController`가 상품별로 채널을 다르게 계산하지 않는다 — `salesChannels` 모델 속성 하나를 모든 카드가 공유한다.
- 나중에 Product-채널 간 실제 연결(또는 Movement 기반 집계)이 필요해지면, 이 칩은 지금처럼 "셀러의 전체 채널"이 아니라 상품별로 달라져야 한다 — 그때는 이 ADR의 결정을 뒤집어야 한다.
- 채널을 하나도 등록하지 않은 셀러는 모든 상품 카드에 칩이 안 뜬다(빈 목록이므로) — 별도 플레이스홀더는 두지 않았다.
