# 채널 연동으로 들어온 상품의 초기재고는 해당 채널을 태그하고, 수기 등록은 계속 채널 없이 기록한다

지그재그 등 외부 채널 연동(`ChannelConnect`)으로 상품을 가져올 때, 각 조합의 초기재고를 INBOUND(신규) 또는 ADJUSTMENT_IN/ADJUSTMENT_OUT(기존 상품 재동기화) Movement로 기록한다. 이때 그 Movement에 출처 채널(예: "지그재그")을 태그할지, 아니면 ADR 0006의 수기 등록 초기재고처럼 채널 없이(null) 기록할지를 정해야 했다.

## Considered Options

- **채널 없이 기록 (기각)**: ADR 0006의 상품 등록 시 초기재고와 동일하게 `salesChannel = null`로 남긴다. 구현은 더 단순하지만, "이 재고가 어느 채널에서 들어왔는지" 연동 이력을 Movement만으로는 알 수 없게 된다.
- **출처 SalesChannel 자동 생성/재사용 후 태그 (채택)**: 연동 시 채널명(예: "지그재그")으로 `SalesChannel`을 자동 생성(이미 있으면 재사용)하고, 그 연동으로 들어온 상품들의 초기재고 Movement에 이 채널을 태그한다. "채널은 Movement의 태그일 뿐"이라는 기존 설계 원칙([0001](./0001-shared-total-stock-across-channels.md))과 일치하고, 멀티채널 출처 추적이 이 프로젝트의 핵심 가치이므로 자연스럽다.

## Consequences

- 상품 등록 화면(수기 입력, ADR 0006)의 초기재고는 계속 `salesChannel = null`로 남는다 — 채널 태그가 있는지 없는지 자체가 "수기로 등록했는지 연동으로 가져왔는지"를 구분하는 신호가 된다.
- 연동 채널명과 겹치는 이름의 `SalesChannel`을 셀러가 이미 수동으로 등록해 뒀다면, 연동은 새로 만들지 않고 그 채널을 그대로 재사용한다 — 셀러가 보기엔 채널이 중복 생성되지 않는다.
- 판매/재고 집계 로직은 Movement 타입(INBOUND/ADJUSTMENT_IN/ADJUSTMENT_OUT 등)으로 먼저 필터링해야 한다 — 채널이 태그돼 있다고 해서 그 Movement가 "판매"를 의미하는 것은 아니며, 입고성 Movement가 판매 집계에 섞이면 안 된다.
